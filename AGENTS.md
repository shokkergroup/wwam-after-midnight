# WWAM Demo Operating Rules

## No-approval lane

- Keep implementation, tests, QA, and release work inside the writable WWAM Demo workspace.
- Do not request terminal or filesystem escalation for ordinary project work.
- If a command path would trigger a permission dialog, use an in-process project tool, browser control, or the Sites connector instead and keep working.
- Use the Sites connector for hosting releases and verify the live URL after deployment.
- Avoid destructive cleanup, broad deletes, and unrelated changes. Preserve source evidence and user work.
- A genuine external authorization requirement may be reported, but it must not be manufactured by choosing an approval-gated workflow when a safe local route exists.
